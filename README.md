# BDON Record

[운영 페이지](https://bdon-record.kh12.workers.dev) · [악곡 미리보기](https://lkh1134.github.io/BDON_Record/)

뱅드림! 아워 노트의 악곡별 플레이 기록을 저장하고 레이팅을 확인하는 웹사이트입니다. 같은 사이트 계정으로 로그인하면 다른 기기에서도 저장한 기록을 이어서 사용할 수 있습니다.

현재 **93곡·372개 차트**와 Expert / Hard / Normal / Easy 난이도를 지원합니다. 악곡 데이터는 2026년 10월 28일 기준으로 MyGO!!!!!의 「논브레스 오블리주」와 Ave Mujica의 「怪物 / KAIBUTSU」를 포함합니다. 2026년 10월 29일에는 기타 분류의 로고를 갱신했습니다.

## 주요 기능

- 계정 만들기·로그인·로그아웃과 계정별 기록 저장
- 곡·난이도별 클리어 / 풀콤보 / 올퍼펙트 선택·해제
- 여러 곡과 난이도의 기록을 편집한 뒤 한 번에 저장·취소
- 곡명·원문·밴드 검색, 밴드·기록 필터와 레벨 정렬
- 난이도별 기록 집계와 차트별·계정 전체 레이팅
- 레이팅에 반영된 상위 50곡의 상세 내역
- 밴드 5개와 기타 분류의 로고, 네이비·블루 테마와 모바일 화면 지원

로그인 없이도 곡 목록·검색·난이도·레벨을 확인할 수 있습니다. GitHub Pages의 악곡 미리보기는 읽기 전용이며, 계정과 기록 저장은 운영 페이지에서 제공합니다.

## 최근 업데이트 · 2026-10-29

기타 분류에 속하는 CRYCHIC 곡의 임시 아이콘을 BanG Dream! Our Notes 로고로 교체했습니다. 제공된 투명 배경 WebP를 사용하며 다른 밴드와 동일한 흰 액자·블루 테두리로 표시합니다. 운영 페이지와 GitHub Pages 미리보기에 모두 반영했습니다.

악곡 데이터·기록·레이팅 계산은 그대로 유지합니다. 전체 테스트 58개와 Workers 배포 전 검증, [Pages 자동 배포](https://github.com/LKH1134/BDON_Record/actions/runs/40813019858)를 통과했습니다.

## 사용 방법

1. 운영 페이지 오른쪽 위 **로그인 → 계정 만들기**에서 계정을 만들거나 기존 계정으로 로그인합니다.
2. **기록 편집**을 누르고 난이도를 선택합니다.
3. 곡 오른쪽의 **클리어 / 풀콤보 / 올퍼펙트** 중 하나를 선택합니다. 다른 상태를 고르면 교체되고, 선택한 상태를 다시 누르면 해제됩니다.
4. **저장**을 누르면 모든 난이도의 변경분을 한 번에 저장합니다. 검색·필터·난이도를 바꿔가며 편집해도 함께 반영됩니다.
5. 변경을 버리려면 **취소**를 누릅니다.

체크를 바꿀 때는 화면의 임시 기록만 갱신합니다. 저장 실패 시 변경분을 유지해 다시 저장할 수 있으며, 취소하거나 변경 없이 종료하면 저장 요청이 발생하지 않습니다. 저장 전 변경은 브라우저 메모리에만 있으므로 새로고침하거나 페이지를 닫으면 사라집니다.

## 레이팅과 집계

차트 레이팅은 **곡 레벨 × 기록 계수**로 계산합니다.

| 기록 | 계수 |
| --- | --- |
| 클리어 | 2.0 |
| 풀콤보 | 2.1 |
| 올퍼펙트 | 2.2 |

한 곡의 여러 난이도 중 가장 높은 레이팅 하나를 선택하고 **상위 50곡을 합산**합니다. 50곡 미만이면 기록한 곡만 합산합니다. 예를 들어 레벨 20 클리어는 40, 레벨 29 올퍼펙트는 63.8입니다.

- 전체 레이팅은 계정의 모든 기록을 사용하며 검색·필터·난이도 탭에 영향을 받지 않습니다.
- 행별 레이팅은 선택한 난이도를 기준으로 표시합니다.
- **상세 보기**에서 합계에 반영된 곡·난이도·기록·점수를 확인할 수 있습니다.
- 클리어 집계에는 풀콤보·올퍼펙트가, 풀콤보 집계에는 올퍼펙트가 포함됩니다.
- 편집 중에는 임시 기록으로 레이팅과 집계를 갱신합니다.

> 해당 레이팅은 공식적인 자료가 아니며, 실력의 척도를 예상하기 위한 가상 지표입니다.

## 악곡 데이터

원본은 `Data.xlsx`이며, `data/catalog.json`으로 변환해 페이지에서 사용합니다.

| 시트 | 내용 |
| --- | --- |
| `Info` | 인덱스 구조, 밴드·분류 코드와 신곡 추가 규칙 |
| `Songs` | 곡 ID, 이름 참조, 밴드, 곡 분류와 난이도별 레벨 |
| `Strings` | 원문·번역명과 이름 참조 ID |

곡 ID는 **밴드 2자리 + 분류 1자리 + 순번 3자리**입니다. `xx1xxx`는 오리지널, `xx2xxx`는 커버이며 현재 오리지널 64곡·커버 29곡을 관리합니다. 예를 들어 `202007`은 Ave Mujica의 커버 7번째 곡입니다. 곡 분류는 엑셀·카탈로그에서 관리하며, 화면에는 별도 분류 필터가 없습니다.

데이터를 수정했다면 Python 3으로 변환하고 원본과 JSON을 함께 반영합니다.

```sh
npm run sync-data
```

발급한 곡 ID와 Strings ID를 유지합니다. 이전 형식의 로컬 DB를 사용하는 경우 [Songs 인덱스·기록 이전 안내](docs/SONG_IDS.md)를 참고합니다.

## 로컬 개발

Node.js 24.15 이상과 Python 3을 준비합니다. Python은 엑셀 변환과 전체 테스트에 사용합니다.

```sh
npm ci
npm run db:local
npm run dev:worker
```

Wrangler가 표시하는 로컬 주소에 접속합니다. 기본 주소는 `http://127.0.0.1:8787`입니다. 로컬 D1은 운영 계정·기록과 분리됩니다.

```sh
npm test
npm run check:worker
```

Node·SQLite 버전은 `npm start` 또는 PowerShell의 `.\start.ps1`로 실행할 수 있습니다. 실행 환경과 별도 DB 지정은 [개발 안내](docs/DEVELOPMENT.md)를 참고합니다.

큰 기능은 `test`에서 개발·검증한 뒤 공개 반영 시 `main`에 병합합니다. `main` 푸시는 GitHub Pages 미리보기를 자동 배포합니다. Workers 운영 배포와 D1 migration은 [Cloudflare 안내](docs/CLOUDFLARE.md)에 따라 별도로 진행합니다.

## 계정과 지원 범위

게임 계정과 별도의 사이트 계정을 사용하며 플레이 기록은 직접 입력합니다. 게임 UID를 통한 기록 자동 수집, 비밀번호 찾기·이메일 인증은 아직 지원하지 않습니다.
