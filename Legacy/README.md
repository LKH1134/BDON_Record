# BDON Record

뱅드림! 아워 노트의 곡 목록과 난이도별 플레이 기록을 관리하는 웹 프로젝트입니다. 현재 91곡을 제공하며, 계정별 기록 저장과 상위 50곡 레이팅 계산을 지원합니다.

| 환경 | 주소 / 용도 |
| --- | --- |
| Cloudflare 운영 | [BDON Record](https://bdon-record.kh12.workers.dev) — 로그인·계정별 D1 기록 저장 |
| GitHub Pages | [악곡 미리보기](https://lkh1134.github.io/BDON_Record/) — 읽기 전용, 로그인·기록 저장 비활성 |
| Node 로컬 | `http://127.0.0.1:3000` — 별도 로컬 SQLite 계정·기록 |

작업 현황과 후속 과제는 [HANDOFF.md](../HANDOFF.md), 코드·API·개발 방법은 [개발 인계](../docs/DEVELOPMENT.md), 게임 계정 연동 검토는 [UID API 조사](../docs/UID_API_RESEARCH.md)를 참고합니다.

Cloudflare Workers·D1 버전은 사용자가 최초 배포를 완료했습니다. D1 `bdon-record` 연결 설정, 로그인·기록 저장 API와 실행·배포 순서는 [Cloudflare 안내](../docs/CLOUDFLARE.md)를 참고합니다. 코드 업데이트 시 `npm run deploy:worker`를 실행합니다.

현재 화면은 캐릭터 이미지의 푸른 배경에 맞춘 네이비·블루 테마입니다. 헤더 캐릭터 아이콘은 적용되어 있으며, **곡명 앞의 임시 약어 아이콘은 다음 작업에서 교체할 예정**입니다. 사용할 이미지와 곡별/밴드별 매핑 기준은 아직 정해지지 않았습니다. [아이콘 교체 인계](../docs/DEVELOPMENT.md#다음-ui-작업-곡-앞-아이콘-교체)에 구현 위치와 배포 시 수정할 파일을 정리했습니다.

## 실행

Windows PowerShell에서 프로젝트 폴더를 열고 실행합니다.

```powershell
.\start.ps1
```

브라우저에서 http://127.0.0.1:3000 에 접속합니다. 종료는 실행한 터미널에서 `Ctrl+C`를 누릅니다. 패키지 설치는 필요하지 않습니다. 실행 스크립트는 시작할 때 `Data.xlsx`를 다시 읽습니다.

직접 실행하려면 Node.js 24 이상과 Python 3이 필요합니다.

```sh
npm run sync-data
npm start
```

포트 변경은 `PORT` 환경변수를 사용합니다. 서버는 `127.0.0.1`에서만 수신합니다.

## 사용

- 오른쪽 위 **로그인 → 계정 만들기**에서 계정을 만듭니다. Cloudflare와 Node 로컬의 계정·기록 저장소는 서로 분리됩니다.
- 아이디는 문자·숫자·밑줄·하이픈 2~24자, 비밀번호는 8~128자입니다.
- **기록 편집**을 누른 뒤 Expert / Hard / Normal / Easy를 고르고 곡 우측의 **클리어 / 풀콤보 / 올퍼펙트** 중 하나를 선택합니다. 난이도·검색·필터를 바꿔도 편집 내용은 유지됩니다.
- 같은 곡과 난이도에는 기록을 하나만 저장합니다. 다른 항목을 고르면 교체하고, 선택한 항목을 다시 누르면 기록을 해제합니다.
- 체크 중에는 저장 요청을 보내지 않습니다. **저장**을 누르면 변경한 기록을 한 번에 전송하고, 성공하면 편집 모드를 종료합니다. 변경이 없으면 통신 없이 종료합니다. 저장한 기록은 로그아웃, 새로고침, 서버 재시작 후에도 유지되며 다른 계정의 기록과 분리됩니다.
- **취소**는 저장 요청 없이 편집 전 기록을 복원합니다. 저장 실패 시 편집 내용을 유지하므로 다시 저장할 수 있습니다. 미저장 상태로 페이지를 떠나면 브라우저가 경고하며, 임시 편집 내용은 새로고침 후 복구되지 않습니다. 편집 중 레이팅과 집계는 임시 기록으로 계산합니다.
- 요약의 클리어 수는 풀콤보·올퍼펙트를 포함하고, 풀콤보 수는 올퍼펙트를 포함합니다. 기록 필터는 선택한 상태와 정확히 일치하는 곡을 표시합니다.
- 레이팅은 `곡 레벨 × 클리어 계수`로 계산하고 상위 50곡을 합산합니다. 계수는 클리어 1.0, 풀콤보 1.05, 올퍼펙트 1.1입니다. 같은 곡의 여러 난이도 중 가장 높은 레이팅 하나만 반영합니다. 기록한 곡이 50곡 미만이면 있는 곡만 합산하며, 난이도 탭이나 검색·필터를 바꿔도 계정 레이팅은 유지됩니다. 화면에는 결과값만 소수점 최대 두 자리로 표시합니다.
- 원문·번역명·밴드로 검색하거나 밴드와 기록 상태로 필터링할 수 있습니다. 번역명이 없으면 원문을 표시합니다.
- 레벨은 선택한 난이도 기준으로 오름차순·내림차순 정렬할 수 있습니다. `기타` 밴드 분류에는 CRYCHIC 악곡이 포함되며 곡의 실제 밴드명은 유지합니다.
- 곡 표의 레벨 왼쪽에는 해당 난이도에서 얻은 레이팅을 표시합니다. 로그인 후 미기록은 `0`, 비로그인은 `—`이며 전체 레이팅은 요약 영역 가장 오른쪽에 표시합니다.

## 데이터

`Data.xlsx`가 곡 데이터의 원본입니다. `Songs`의 곡 ID와 스트링 참조, `Strings`의 원문·번역명을 `scripts/import_data.py`가 `data/catalog.json`으로 변환합니다. 변환은 엑셀을 수정하지 않습니다. 곡 ID를 바꾸면 기존 기록과의 연결이 바뀌므로 기존 ID는 유지합니다.

Cloudflare 운영의 계정·세션·기록은 D1에 저장합니다. Node 로컬 버전은 `.local/bdon.sqlite`, Workers 로컬 개발은 `.wrangler/`의 별도 D1을 사용합니다. 비밀번호는 무작위 salt와 scrypt로 해싱하고, 세션은 HttpOnly 쿠키로 관리합니다. 로컬 DB 파일은 Git에서 제외합니다. `.local/bdon.sqlite`를 지우면 모든 Node 로컬 계정과 기록이 삭제됩니다. 해당 서버를 종료한 뒤 `.local` 폴더를 복사해 백업할 수 있습니다.

## 검증

```sh
npm ci
npm test
```

개발 의존성·전체 테스트에는 Node.js 24.15 이상이 필요합니다. 최근 확인한 전체 테스트는 **47개 통과**이며, 네이비 테마 커밋의 [GitHub Actions](https://github.com/LKH1134/BDON_Record/actions/runs/40315790205)도 성공했습니다.

자동 검증은 프런트엔드 jsdom에서 편집 중 통신 없음·저장 요청 1회·취소·실패 후 재시도를 확인합니다. Node와 실제 Workers 로컬 런타임·임시 D1에서는 가입·로그인·로그아웃, 계정별 격리, 전체 364차트 일괄 저장과 오류 시 롤백, 재시작 후 유지, 요청 검증과 접근 제한을 확인합니다. 테스트는 임시 DB를 사용하며 실제 계정과 원격 D1에 영향을 주지 않습니다. 기존 Node.js 로컬 서버만 실행할 때는 외부 npm 패키지가 필요하지 않습니다.

## 배포

GitHub Pages용 공개 미리보기와 로컬 계정 버전을 함께 유지합니다. 공개본은 곡 목록·검색·필터·난이도 선택·레벨 정렬을 제공하며 로그인과 기록 저장은 비활성화합니다. 계정·기록·개인 레이팅은 로컬 서버 또는 배포한 Cloudflare 주소에서 사용할 수 있으며 두 환경의 DB는 분리됩니다. 게임 UID 연동은 아직 구현하지 않았습니다.

```sh
npm run sync-data
npm run build:pages
```

`dist/`에 헤더 아이콘을 포함한 공개 자산 7개만 생성합니다. 계정 DB, 엑셀, 서버 코드, 인계 문서는 배포 파일에 포함하지 않습니다. 기존 출력 폴더에 예상하지 않은 파일이 있으면 빌드는 공개를 중단합니다.

`.github/workflows/pages.yml`은 `main` 푸시 또는 수동 실행 시 엑셀 변환·테스트·정적 빌드를 수행하고 Pages에 배포합니다. 저장소 Settings → Pages → Source는 **GitHub Actions**로 설정해야 합니다. 자세한 설정과 확인 방법은 [Pages 배포 인계](../docs/DEPLOYMENT.md)를 참고합니다.

Cloudflare 운영 페이지는 별도로 업데이트합니다. 저장소에 포함된 workflow는 Pages용이며, Cloudflare 자동 배포 연결은 확인되지 않았으므로 GitHub 푸시만으로 Workers가 갱신된다고 가정하지 않습니다.

```sh
npm run check:worker
npm run deploy:worker
```

편집 모드와 네이비 테마 변경에는 DB migration이 필요하지 않습니다. 다음 아이콘 작업에서 이미지가 추가되면 현재 자산 7개 허용 목록과 빌드·테스트도 함께 갱신해야 합니다.
