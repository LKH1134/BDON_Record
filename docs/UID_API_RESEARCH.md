# UID를 통한 게임 기록 조회 조사

조사일: 2026-10-26. 대상은 **BanG Dream! Our Notes(뱅드림! 아워 노트)**이며 기존 Girls Band Party 자료와 구분했습니다. 조사 결과는 해당 날짜의 공개 문서 기준이며 실제 사용자 UID로 동기화를 검증한 결과가 아닙니다.

## 결론과 현재 구현

UID만으로 계정의 모든 악곡·난이도별 클리어 / 풀콤보 / 올퍼펙트 상태를 가져오는 공개 API는 조사 범위에서 확인하지 못했습니다. 공식 개발자용 API 문서도 찾지 못했습니다. 이는 API가 존재하지 않는다는 확정은 아닙니다.

공개 프로필·랭킹 조회용 비공식 API와 사용자 승인 기반 저장 데이터 다운로드 기능은 확인했습니다. 프로젝트에는 어느 서비스도 연결하지 않았으며 기록은 현재 직접 선택해 저장합니다.

## Haneoka

- [소개](https://docs.haneoka.org/getting-started/introduction/)
- [Game records API](https://docs.haneoka.org/reference/game-records/)
- [OpenAPI 명세](https://docs.haneoka.org/openapi.json)
- [실제 API 소비 예시인 Tomori 봇 저장소](https://github.com/haneoka-gakuen/tomori-ournotes-bot)

문서에는 인증 없이 공개 프로필을 조회하는 다음 경로가 있습니다.

```text
GET https://haneoka.org/api/v1/game/records/{region}/players/{profileId}
```

`profileId`는 게임 내 공개 플레이어 ID입니다. 지원 지역은 `jp`, `tw`, `en`, `kr`이며 한국 서버는 `kr`입니다. 문서상 한국 서버 ID는 4로 시작하는 11자리 문자열입니다. 프로필에는 이름, 랭크 경험치·레벨, 좋아요, 대표 카드, 프로필 카드 이미지 정보가 정의되어 있습니다. 응답은 60초 캐시를 사용하며 갱신 대기·오래된 데이터·상위 서비스 오류가 발생할 수 있습니다.

곡별 점수 랭킹과 이벤트 랭킹도 제공하지만, 확인한 문서와 명세에는 **플레이어의 전체 난이도별 클리어 상태 목록**이 없습니다. 랭킹 점수나 프로필 카드 이미지로부터 모든 곡의 clear/fc/ap 상태를 추정해서는 안 됩니다. 예시 UID의 실제 API 응답은 조사 도구에서 열리지 않아 검증하지 못했습니다.

## Moenotes

- [Open Platform 진입 페이지](https://bdon.moe/en/open-platform)
- [Open Platform 문서](https://open-platform.bdon.moe/)
- [저장 데이터 승인·다운로드 문서 링크](https://open-platform.bdon.moe/guides/saves.html)
- [사이트 소스](https://github.com/StarMoe-org/moenotes)

문서 첫 페이지에는 공개 프로필·랭킹 조회와 **사용자가 승인한 gzip 저장 데이터 다운로드**가 소개되어 있습니다. 서비스 자체가 게임 공식 API가 아님을 명시합니다. 개발자 앱을 등록해 `clientID`와 Secret을 발급받고 사용자에게 저장 데이터 접근 승인을 받는 흐름입니다.

저장 데이터 상세 문서는 조사 중 타임아웃·접근 실패로 읽지 못했습니다. 따라서 다음 사항은 **미확인**입니다.

- 저장 데이터에 전곡·난이도별 클리어/FC/AP 필드가 실제 포함되는지.
- 데이터 최초 등록·갱신 방법, 게임 플레이 이후 반영 시점과 누락 범위.
- 각 지역 지원 범위, 구체적인 저장 데이터 다운로드 계약 및 인증 조건.

UID만 입력하는 기능과 사용자 승인이 필요한 저장 데이터 다운로드는 구분해야 합니다. 현재로서는 후자가 자동 가져오기를 검토할 후보입니다.

## 후속 검증 순서

1. 최신 API 문서와 저장 데이터 계약을 다시 확인합니다.
2. 사용자가 제공·승인한 계정 데이터로 곡 ID, 난이도, clear/fc/ap 필드와 갱신 시각을 확인합니다.
3. 게임 내 기록과 대조해 올퍼펙트·풀콤보·일반 클리어·미플레이 및 실패 상태를 구분합니다.
4. 외부 서비스 곡 ID와 현재 `Data.xlsx`의 곡 ID 사이에 명시적인 대응표를 만듭니다.
5. 수동 기록과 충돌할 때의 처리 및 가져오기 전 미리보기를 정한 후 사이트 연동을 구현합니다.

조사 과정에서 개발자 앱 생성, 사용자 데이터 다운로드, 외부 서비스로 메시지 전송은 하지 않았습니다.
