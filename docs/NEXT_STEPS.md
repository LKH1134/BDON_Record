## 1. 곡의 앨범 재킷 포함 여부 검토

상태: **검토 필요, 포함 여부 미결정**.

현재 악곡 앞에는 5개 밴드의 로고를 흰 액자·블루 테두리 안에 표시합니다. 아직 곡별 앨범 재킷 데이터나 이미지는 연결하지 않았습니다.

다음 작업에서 확인할 사항:

- 밴드 로고와 앨범 재킷을 함께 표시할지, 재킷으로 교체할지
- 곡별 재킷 이미지와 곡 ID의 연결, 이미지가 없는 곡의 대체 표시
- 데스크톱·모바일에서 곡명·기록 체크박스와의 배치, 이미지 용량과 로딩 방식
- 자산이 추가되면 Node 정적 경로, Pages·Workers 빌드 허용 목록·복사 로직과 자산 테스트 갱신

관련 위치: `public/app.js`의 `bandLogos` / `renderSongs()`, `public/styles.css`의 `.band-logo-frame`, `public/band-logos/`, `scripts/build-pages.mjs`. 현재 구현은 [개발 인계](DEVELOPMENT.md#곡-앞-밴드-로고)를 참고합니다.

## 2. 레이팅 계산값 2배 변경 — 직관성 패치

상태: **구현·검증·`main` 병합·운영 배포 완료** (2026-10-27).

- 공식: 차트 레이팅 = `곡 레벨 × 기록 계수`
- 변경 전 계수: 클리어 1.0 / 풀콤보 1.05 / 올퍼펙트 1.1
- 현재 운영 계수: 클리어 2.0 / 풀콤보 2.1 / 올퍼펙트 2.2. 계수 자체를 변경했으므로 계산 결과에 다시 2를 곱하지 않습니다.
- 곡마다 최고 차트 하나를 고른 뒤 상위 50곡을 합산하는 규칙을 유지합니다.

공통 계산 함수의 계수를 변경해 전체 레이팅, 곡별 획득 레이팅, 상세 보기의 각 점수·합계에 같은 기준으로 반영했습니다. 운영 배포 버전은 `8349cbc1-d6ed-4baa-a4d5-7dd834c83e86`이며 운영의 계산 코드가 검증한 로컬 코드와 일치함을 확인했습니다.

구현·검증 위치:

- `public/rating.js`: `calculateChartRating()`, `getRatingBreakdown()`, `calculateRating()`의 결과 일치와 정수 기반 합산 정밀도
- `public/app.js`: 메인 합계·행별 점수·상세 보기·임시 편집·취소 후 복원
- `tests/rating.test.mjs`, `tests/editor.test.mjs`, `tests/worker.test.mjs`: 기존 점수 기대값과 상세 합계 일치, 상위 50곡·동점·중복 차트 규칙 유지
- README·HANDOFF·인계 문서와 `레이팅 계산식.txt`: 변경한 계수·검증 예시와 운영 배포 완료 상태를 반영

검증 예시: 레벨 20 클리어 `20 → 40`, 레벨 29 AP `31.9 → 63.8`, 레벨 29 AP 50곡 합계 `1595 → 3190`. 기존 곡별 최고 차트와 상위 50곡 선정·동점 규칙을 유지합니다. 전체 테스트 53개 통과로 계산·편집·취소·상세 합계와 Workers 저장 기록의 재계산을 확인했습니다.

레이팅은 DB에 저장하는 값이 아니라 카탈로그와 기록으로 계산합니다. 현재 데이터 구조 기준으로 이 변경만을 위해 계정·기록을 초기화하거나 DB migration을 추가할 필요는 없습니다.
