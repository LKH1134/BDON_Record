# 다음 작업 메모

기록일: 2026-10-26. 사용자가 **다음 작업 세팅 시 반드시 언급**해 달라고 지정한 두 항목입니다. 이번 작업은 문서 정리이며 아래 기능은 아직 적용하지 않았습니다.

## 시작할 때 안내할 내용

> 다음 작업 메모는 곡의 앨범 재킷 포함 여부 검토와 레이팅 계산값 2배 변경(직관성 패치)입니다. 현재는 밴드 로고를 사용하고 있으며, 레이팅 2배 변경은 아직 적용되지 않았습니다.

새 작업·새 세션의 시작 안내에서 위 내용을 먼저 알립니다. 메모를 읽었다는 이유만으로 문서 정리 중에 런타임 동작을 바꾸지 않습니다. 사용자가 후속 작업의 범위나 순서를 바꾸면 최신 지시를 반영합니다.

## 1. 곡의 앨범 재킷 포함 여부 검토

상태: **검토 필요, 포함 여부 미결정**.

현재 악곡 앞에는 5개 밴드의 로고를 흰 액자·블루 테두리 안에 표시합니다. 아직 곡별 앨범 재킷 데이터나 이미지는 연결하지 않았습니다.

다음 작업에서 확인할 사항:

- 밴드 로고와 앨범 재킷을 함께 표시할지, 재킷으로 교체할지
- 곡별 재킷 이미지와 곡 ID의 연결, 이미지가 없는 곡의 대체 표시
- 데스크톱·모바일에서 곡명·기록 체크박스와의 배치, 이미지 용량과 로딩 방식
- 자산이 추가되면 Node 정적 경로, Pages·Workers 빌드 허용 목록·복사 로직과 자산 테스트 갱신

관련 위치: `public/app.js`의 `bandLogos` / `renderSongs()`, `public/styles.css`의 `.band-logo-frame`, `public/band-logos/`, `scripts/build-pages.mjs`. 현재 구현은 [개발 인계](DEVELOPMENT.md#곡-앞-밴드-로고)를 참고합니다.

## 2. 레이팅 계산값 2배 변경 — 직관성 패치

상태: **후속 구현 예정, 현재 미적용**.

- 현재: 차트 레이팅 = `곡 레벨 × 기록 계수`
- 변경 예정: 차트 레이팅 = `곡 레벨 × 기록 계수 × 2`
- 계수는 클리어 1.00 / 풀콤보 1.05 / 올퍼펙트 1.10, 곡마다 최고 차트 하나를 고른 뒤 상위 50곡을 합산하는 규칙을 기준으로 작업합니다.

전체 레이팅뿐 아니라 곡별 획득 레이팅과 상세 보기의 각 점수·합계를 같은 기준으로 2배 적용해야 합니다. 현재 2배 변경을 완료한 것으로 표시하거나, 총합만 두 배로 만들어 상세 목록과 불일치하게 두지 않습니다.

후속 구현·검증 위치:

- `public/rating.js`: `calculateChartRating()`, `getRatingBreakdown()`, `calculateRating()`의 결과 일치와 정수 기반 합산 정밀도
- `public/app.js`: 메인 합계·행별 점수·상세 보기·임시 편집·취소 후 복원
- `tests/rating.test.mjs`, `tests/editor.test.mjs`, `tests/worker.test.mjs`: 기존 점수 기대값과 상세 합계 일치, 상위 50곡·동점·중복 차트 규칙 유지
- README·HANDOFF·인계 문서와 `레이팅 계산식.txt`: 실제 패치 시 현재 적용 공식과 검증 예시 갱신

예정 검증 예시: 레벨 20 클리어 `20 → 40`, 레벨 29 AP `31.9 → 63.8`, 레벨 29 AP 50곡 합계 `1595 → 3190`. 모두 같은 양의 배수를 적용하므로 기존 곡별 최고 차트와 상위 50곡의 선정 순서는 유지되어야 합니다.

레이팅은 DB에 저장하는 값이 아니라 카탈로그와 기록으로 계산합니다. 현재 데이터 구조 기준으로 이 변경만을 위해 계정·기록을 초기화하거나 DB migration을 추가할 필요는 없습니다.
